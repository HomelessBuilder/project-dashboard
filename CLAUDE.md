# Project Dashboard — Project Manager Context

## What This Project Is

Two pages, both generated by `generate.py`, both opened directly in a
browser:

- **`index.html`** — the hub. The front door into the meta-system: a
  short "needs attention" section (stalled sessions, disk space,
  decisions awaiting review — all computed live at generation time) plus
  link tiles out to the actual tools (project status, open sessions,
  transcripts, journal, latest audit, decision log, idea bank, monitor
  reports). Open this first.
- **`dashboard.html`** — the project-status page. Every registered
  project's current status (from devlog-engine) overlaid with which ones
  have a live Claude Code session open right now. One of the hub's link
  tiles, not the entry point.

This is an exploratory prototype and visual thinking tool, not a
production system. Structure and features emerge from use, not from
upfront design — the hub/status-page split above is itself the product
of one round of that (2026-07-27, see below), not a fixed design.

## Data Sources

**devlog-engine is the backend**, not flat files — this changed
2026-07-27 (see `PROTOTYPE-BUILD-BRIEF.md`'s "Backend Roadmap" section,
which planned this swap back when devlog-engine was still pre-code; it
has since landed and become the sole system of record). `generate.py`
calls the `devlog` CLI (`status`, `projects`) — never reads `CURRENT.md`
or `DEVLOG.md` directly, and shouldn't; those are now frozen historical
files, not live data.

Everything else `generate.py` reads, all read-only, all local:
- `~/.claude/sessions/*.json` — the live process registry (which
  sessions are actually open right now, and their status)
- `~/DECISION-LOG.md` — count of decisions still awaiting review
- disk usage via Python's `shutil` (no shelling out, no sudo)
- `~/bored_audits/`, `~/idea-bank/IDEA-LOG.md`, `~/monitor/reports/` —
  linked from the hub, not parsed for content

`~/monitor/reports/CONCERNS.md` is deliberately **not** surfaced in the
attention section — checked 2026-07-27 and it hadn't been updated since
2026-07-02, consistent with reliability gaps found in monitor review
sessions that week. Stale data shown as current would be worse than no
data. Revisit this once monitor's own reliability work lands.

This project does not modify, extend, or depend on any other project's
internals — it only reads their public-facing data (devlog-engine's CLI,
not its database file directly; other projects' generated output files,
not their source). No changes are ever made to another project's files.

## Technical Approach

Standalone HTML files — no build step, no framework, no server required
for either page (some of the hub's linked destinations, like the
transcript viewer and journal, do need a local server running; the hub
says so on each tile that needs one). Regenerate on demand:

```
python3 ~/project-dashboard/generate.py
```

## What It Is Not

- Not a live-updating system (regenerated on demand, not real-time)
- Not a production tool for clients or students
- Not a replacement for any existing project
- Not a permanent architecture decision — it's a sketch, currently one
  iteration into "hub + destinations," with more iteration expected as
  Diego actually uses it day to day
